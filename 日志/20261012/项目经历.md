# 二、可以写进简历的项目经历

我建议项目名不要叫 `mini-agent`，简历里可以写得正式一点：

### 科研论文智能分析 Agent

**技术栈：** Python、LangGraph、LangChain、FastAPI、ChromaDB、SQLite、DeepSeek API、OpenAlex、BGE-M3、BGE-Reranker

**项目描述：**
面向科研论文检索与分析场景，设计并实现基于 LangGraph 的多阶段 Research Agent，支持复杂科研任务的自动规划、论文检索、内容读取、知识库检索和结果分析。

**主要工作：**

* 基于 **LangGraph** 构建 Router–Planner–Executor 工作流，通过 State 驱动节点执行，实现复杂科研任务的多阶段编排。
* 设计基于  **LLM 的动态能力路由机制** ，根据当前任务步骤自动选择论文检索、论文读取、本地 RAG 或推理分析模块。
* 集成  **OpenAlex 学术检索接口** ，实现论文元数据检索，并基于 DOI / OpenAlex ID 获取摘要信息，完成论文方法、数据集及优缺点提取。
* 构建基于 **BGE-M3 + ChromaDB + BGE-Reranker** 的本地论文 RAG 流程，实现向量召回、重排序和上下文增强生成。
* 使用 **LangGraph Checkpoint + SQLite** 实现 Agent 状态持久化，支持任务中断、恢复及同一任务线程续跑。
* 实现 **Human-in-the-loop** 机制，在外部论文检索等关键操作前增加人工确认。
* 使用 **FastAPI** 搭建 Agent Gateway，支持 HTTP 请求、新任务自动生成 `thread_id`、已有任务线程复用，并为后续流式输出和前端接入预留接口。

这个版本已经可以放进简历。

> 集成 OpenAlex 学术检索与 BGE-M3 + ChromaDB + Reranker RAG 流程，实现论文搜索、摘要读取、方法/数据集/优缺点提取及多论文比较。
> 基于 SQLite Checkpoint 实现 Agent 状态持久化与任务恢复，并使用 FastAPI 搭建 Gateway，支持 thread 自动创建、复用及 HTTP 服务化调用。
