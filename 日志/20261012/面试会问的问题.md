# 三、面试官大概率会问什么

你这个项目面试官不会只问“你做了什么”，更可能顺着架构往下挖。

### 1. 为什么要用 LangGraph，直接 while 循环不行吗？

你可以答：

> 简单 Agent 用 while 循环也可以，但随着 Router、Planner、Executor、人工确认和多个能力节点增加，执行路径会变复杂。LangGraph 能显式定义节点、边、State 和 Checkpoint，更适合需要分支、循环、中断和恢复的 Agent 工作流。

核心点：

```
不是为了“用了框架”
而是为了：
状态驱动 + 条件路由 + 循环 + 持久化
```

### 2. Router 和 Executor 有什么区别？

这是非常容易被问的。

你可以说：

> Router 判断的是整个用户请求应该进入哪条主流程，比如直接回答、RAG、论文检索还是 Planner；Executor 则是在 Planner 已经生成计划后，根据当前具体步骤选择实际执行能力。

例如：

```
Router：
“这个问题是不是复杂任务？”

Executor：
“复杂任务的第3步应该调用 paper_read 还是 reasoning？”
```

### 3. Planner 和 Executor 为什么不合在一起？

答：

> Planner 负责制定计划，Executor 负责执行计划。分开后可以降低 Planner prompt 的复杂度，同时允许 Executor 在执行过程中结合最新 State 动态选择能力，而不是一开始就把所有工具绑定死。

### 4. Executor 为什么用 LLM 决策，不直接写 if else？

答：

> 如果步骤类型很固定，可以用规则判断；但 Planner 输出是自然语言步骤，LLM 对自然语言任务意图的识别更灵活。当前使用 LLM routing，同时限制允许返回的 action，避免输出非法能力。后续可以结合规则和 LLM，减少成本和不确定性。

这个回答很重要，因为你之前真遇到过：

```
LLM 返回 direct_answer
→ KeyError
```

所以你可以继续说：

> 实际开发中我也遇到过模型输出未定义 action 导致路由失败，因此增加了 allowed_actions 校验。

这个非常像真实项目经验。

### 5. State 和 Memory 有什么区别？

你现在应该能答得很好：

> State 是当前任务执行过程中的共享状态，例如当前步骤、计划、检索结果和已选论文；Memory 更偏长期、跨任务保存的信息。Checkpoint 保存的是某个时刻的 State 快照，用来恢复任务。

一句话：

```
State = 当前任务工作台
Checkpoint = 工作台快照
Memory = 长期记忆
```

### 6. thread_id 有什么作用？

答：

> thread_id 用于标识一个任务上下文。LangGraph Checkpointer 会根据 thread_id 找到对应的历史 State，因此同一个 thread_id 可以继续之前的任务，不同 thread_id 相互隔离。

### 7. run 和 thread 有什么区别？

可以说：

> thread 表示一个持续的任务上下文，而 run 表示该 thread 中的一次具体执行。一个 thread 可以包含多次 run。

### 8. 为什么 paper_search 搜到了论文，local_rag 却读不到？

这个问题非常适合你项目经历。

答：

> 因为 paper_search 搜到的是外部论文元数据，只存储在 State 的 `selected_papers` 中，并没有进入本地 Chroma；local_rag 只能访问已经提前向量化的本地论文库。所以后来单独增加了 paper_read 能力，根据 OpenAlex ID 或 DOI 读取新检索论文。

这其实是你当前架构演化里非常漂亮的一点。

### 9. 为什么不把搜索到的论文直接存进 Chroma？

答：

> 临时检索到的论文不一定需要长期保存。如果每次检索都直接写入向量库，会造成知识库污染和重复数据。因此当前把临时论文保存在 State，通过 paper_read 使用；只有明确需要长期沉淀的文献，再进入 Chroma。

这个回答挺加分。

### 10. RAG 的流程是什么？

你的答案：

```
用户 query
→ Query Rewrite
→ BGE-M3 Embedding
→ Chroma Top-K 召回
→ BGE-Reranker 重排序
→ 取 Top-N
→ LLM 生成回答
```

然后面试官可能接着问：

> 为什么需要 reranker？

答：

> 向量召回主要保证召回率，但向量相似度不一定等于语义相关性，因此使用 reranker 对候选文档进一步精排，提高最终上下文质量。

### 11. 为什么需要 Checkpoint？

答：

> Agent 是多步骤任务，可能遇到人工确认、程序中断或网络失败。Checkpoint 可以保存当前 State，使任务能够从之前的执行位置恢复，而不需要从头执行。

### 12. Human-in-the-loop 用在什么地方？

答：

> 当前用于外部论文检索前的人工确认。核心思想是对外部调用、成本较高或有副作用的操作增加人为审批。

以后可以扩展到：

```
发邮件
修改文件
调用付费 API
执行代码
```

### 13. Gateway 负责什么？

你刚学过，可以这样说：

> Gateway 是 Agent 系统的入口层，负责接收 HTTP 请求、参数校验、鉴权、thread 管理、幂等控制，并把请求交给 Runtime 执行，同时负责将执行结果返回前端。

如果做流式：

> Runtime 产生 token 或 event，Gateway 通过 SSE 或 WebSocket 转发给前端。

### 14. 目前项目最大的不足是什么？

不要说“没有不足”。

可以答：

> 目前 paper_read 主要依赖 OpenAlex 摘要，全文解析能力还不完整；Gateway 目前只完成基础 thread 管理，流式输出、run 管理、异常恢复和幂等机制还需要继续补充。

这个回答反而显得你清楚系统边界。
