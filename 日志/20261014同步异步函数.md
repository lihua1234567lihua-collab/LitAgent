同步函数你可以先理解成：

> **一件事没做完，就不会往下执行。**

比如普通 Python 函数：

```
def read_paper():    pdf = download_pdf()    text = parse_pdf(pdf)    return text
```

执行顺序是：

```
download_pdf()
↓
等它彻底结束
↓
parse_pdf()
↓
再继续
```

这就是 **同步** 。

而异步函数通常写成：

```
async def download_paper():    ...
```

调用时一般要：

```
result = await download_paper()
```

它适合这种“需要等待”的操作，比如：

```
网络请求
下载文件
访问数据库
调用 MCP
```

因为程序在等网络响应的时候，可以暂时去做别的事情，而不是一直卡在那里。

你现在这两个函数正好就是两种：

```
def resolve_paper_content(...):
```

这是 **同步函数** 。

而：

```
async def download_paper_with_fallback(...):
```

这是 **异步函数** 。

所以现在会产生一个问题：

```
def resolve_paper_content(...):    result = download_paper_with_fallback(...)
```

这样是不对的，因为异步函数不会像普通函数一样直接执行完并返回结果，它会先返回一个 coroutine 对象。

正确的异步调用通常是：

```
result = await download_paper_with_fallback(...)
```

但 `await` 又只能正常出现在：

```
async def ...
```

里面。

所以后面我们大概率会变成：

```
async def resolve_paper_content(...):    result = await download_paper_with_fallback(...)
```

然后 Graph 里的 `paper_read_node` 也要考虑是否改成异步节点。

你先记住一句就够了：

```
同步：做完当前事情，再做下一件事
异步：遇到等待操作时，当前 coroutine 暂停自己的执行，把当前 Python 异步程序的调度控制交回 event loop。
```

你现在先确认一下：你能理解为什么“下载论文”特别适合写成异步函数吗？
